# Калькулятор тарифа — ТЗ 2, Осенний хакатон INAI 2026

По детализации абонента за 3 месяца подбирает самый дешёвый вариант «тариф + 0–2 доппакета»
и говорит, стоит ли переходить с учётом платы 50 сом за смену тарифа.

## Запуск (одна команда)

Требуется **JDK 17+** и **Maven 3.8+** (при первой сборке Maven скачивает зависимости — нужен интернет).
`run.sh` сам находит Java 17+ (`JAVA_HOME`, `/usr/libexec/java_home`, Homebrew, `/usr/lib/jvm`), даже если
по умолчанию в системе стоит Java 8; если подходящей Java нет — пишет, что установить.

```bash
./run.sh data/usage_P01.csv
```

`run.sh` сам соберёт jar при первом запуске. Без скрипта:

```bash
mvn -q package -DskipTests && java -jar target/tariff-calc.jar data/usage_P01.csv
```

В `data/` лежат открытые данные организаторов (`02_tariffs`): тарифы, доппакеты, `subscribers.json`,
10 детализаций и `expected.json`. Текущий тариф и месяцы расчёта берутся из `subscribers.json`.

Другие режимы:

```bash
./run.sh data --jury                           # все абоненты из subscribers.json → массив в формате expected.json
./run.sh path/usage_P07.csv --data-dir data    # tariffs/addons/subscribers из другой папки
./run.sh data/usage_P03.csv --current T02      # явно задать текущий тариф
./run.sh data --jury --out result.json         # сохранить JSON в файл
```

Тесты: `mvn test` — 88 тестов (JUnit 5), позитивные и негативные:

- `TzEdgeCasesTest` — 12 граничных сценариев ТЗ: звонок 0 с, 1 с, 60/61 с; ровно лимит; превышение на
  1 секунду / 1 МБ / 1 SMS; нулевое потребление за 3 месяца; сессии 00:45–01:15 и 06:45–07:15; роуминг
  отдельно от пакетов и ночи; экономия ровно 50 сом за 3 месяца → «остаться»; 51 сом → «перейти»;
  0–2 доппакета, в том числе два одинаковых;
- `EdgeCasesTest` — 16 граничных случаев на маленьких тестовых тарифах;
- `OrganizerExpectedTest` — **сверка с эталонами организаторов**: 10 абонентов `expected.json` и
  12 наборов `edge_cases` — все совпадают;
- `ExplainerTest` — объяснение простым языком использует точные цифры расчёта;
- `RecommendFieldsTest` — поля ответа для сайта: расход по месяцам совпадает с агрегацией, части счёта
  складываются в итог, перебрано 50 вариантов, лимиты совпадают с каталогом, ночной трафик отделён,
  выбранный вручную тариф перекрывает subscribers.json; негативные — неизвестный тариф, нет колонок,
  битые строки и отрицательные объёмы;
- `WebServerTest` — настоящий HTTP-сервер: главная, каталоги, `/api/validate` (корректный, частично битый,
  пустой, без колонок, все строки битые, GET), `/api/recommend` с выбранным тарифом и без него, параллельный
  пакет с битым файлом, защита от обхода каталогов, несуществующий пример, мусор вместо CSV, 404.

### Веб-форма (бонус)

```bash
./run.sh --serve 8080
```

Откройте http://localhost:8080. Загрузите CSV перетаскиванием или выберите пример из `data/`,
при необходимости укажите текущий тариф. Страница покажет вердикт, экономию, график
сравнения тарифов (лучший вариант на каждом тарифе, без доппакетов, линия текущей стоимости)
и разбивку по месяцам. График нарисован без внешних библиотек и работает без интернета.

**Сравнение потребления** (бонус ТЗ «график сравнения тарифов») — сразу под вердиктом две карточки: слева
текущий тариф, справа рекомендуемый (если советуем остаться — ближайшая альтернатива). В каждой столбики
«Стоимость», «Интернет», «Звонки», «SMS»: высота — средний расход за месяц, чёрная линия — лимит тарифа
(для стоимости — абонплата + пакеты). Всё выше линии подсвечивается: оранжевым, если перерасход до 25% лимита,
красным — если больше; ночной трафик на «Ночном» — штриховкой. Шкала у каждого показателя общая для обеих
карточек. Внизу карточек — итог в месяц и экономия, под ними — «Итог» с учётом платы 50 сом.

**Пакетный расчёт.** В рамку можно перетащить сразу несколько CSV (или нажать «Рассчитать все примеры»
в режиме «Пример»). Файлы не считаются автоматически: каждый проверяется тем же парсером (`POST /api/validate`)
и встаёт в список со статусом «Выберите тариф»; битый файл выделяется красным с логом и в работу не идёт.
Нажатие на абонента открывает окно выбора текущего тарифа → `recommend()` считает только этого абонента →
открывается полный разбор (сравнение потребления, месяцы, объяснение) с кнопками «Назад ко всем абонентам»,
листанием и «Тариф «…» · изменить». Выбор запоминается для файла (localStorage): при повторном открытии и при
повторной загрузке того же файла абонент сразу считается с этим тарифом. Сводка — KPI, таблица со статусами,
экспорт в JSON и CSV. Если в форме выбран тариф, он применяется ко всем файлам пакета.

**Онбординг.** При заходе на сайт первым делом на весь экран открывается анимированная
инструкция из 6 шагов (один раз за сессию вкладки), калькулятор — после неё. Слева — уменьшенная копия интерфейса, где курсор сам выполняет каждый шаг:
выбирает источник данных → перетаскивает `usage_P03.csv` в рамку → открывает список «Текущий тариф» →
нажимает «Подобрать тариф» → наводит на строки графика → нажимает «Объяснить». Рядом — описание, что
делает каждая кнопка. Цифры в анимации — настоящий расчёт абонента P03 из данных организаторов.
Шаг повторяется по кругу; листать — «Назад»/«Далее», точки или стрелки на клавиатуре;
«Перейти к калькулятору», «Пропустить» или `Esc` открывают калькулятор. Открыть снова — «Как это работает» в шапке.
При `prefers-reduced-motion` анимации отключены и сразу показывается итог шага.

API:

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/tariffs` | список тарифов |
| GET | `/api/samples` | примеры `usage_*.csv` из папки данных |
| POST | `/api/recommend?name=usage_3.csv&current=T1` | тело — текст CSV, ответ — JSON `recommend()` |
| GET | `/api/recommend?sample=usage_3.csv` | расчёт по примеру |
| POST | `/api/explain` | тело — JSON `recommend()`, ответ — `{explanation, source}` |

### Объяснение через LLM (бонус)

```bash
export ANTHROPIC_API_KEY=sk-ant-...      # ключ команда приносит сама
./run.sh --serve 8080                    # кнопка «Объяснить» на странице
./run.sh data/usage_8.csv --explain      # или в CLI: поле explanation в JSON
```

- Модель `claude-opus-5-5` через официальный Java SDK (`com.anthropic:anthropic-java`),
  низкий уровень effort (короткий текст по готовым фактам), серверный фолбэк при отказе модели.
- **LLM ничего не считает.** В промпт уходят уже посчитанные факты (стоимости, рекомендация,
  сравнение тарифов), модели запрещено придумывать числа.
- Без ключа, при ошибке сети или API — показывается шаблонный текст (`source: "template"`),
  поэтому демо и автопроверка не зависят от интернета. Без `--explain` CLI вообще не обращается к LLM.

## Входные данные

| Файл | Содержимое |
|---|---|
| `tariffs.json` | `{"tariffs": [{id, name, fee, minutes, gb, sms, overage{call,data,sms}, night_unlimited}], "roaming_rates": {call,data,sms}}` |
| `addons.json` | доппакеты: `id, name, fee, minutes, gb, sms` |
| `usage_<id>.csv` | `date, type (call/sms/data), amount, duration_sec, roaming`; call — секунды, data — **ГБ**, sms — штуки |
| `subscribers.json` | `[{id, current_tariff_id, months: [3 месяца], usage_file}]` |

Загрузчик понимает синонимы полей (`monthly_fee`, `overage{...}`, `roaming_*`, тип `roaming_call` и т.п.),
разделители `,` `;` и TAB, запятую в числах, несколько форматов даты. Битые строки пропускаются и
считаются в `skipped_rows`.

Текущий тариф ищется по порядку: `--current` → колонка `tariff` в CSV → `subscribers.json`.
Если его нет нигде, сервис всё равно подбирает самый выгодный вариант (`action: "best"`),
но экономию не считает.

## Выход

Первые поля — в формате эталона организаторов (с `--jury` выводятся только они):

```json
{
  "id": "P10",
  "action": "change",
  "tariff_id": "T01",
  "addon_ids": ["A01"],
  "current_monthly_cost": 700.00,
  "new_monthly_cost": 243.33,
  "monthly_savings": 456.67,
  "switch_fee": 50.00,
  "net_savings_3m": 1320.00,
  "monthly_costs": {"2026-08": 265.00, "2026-09": 200.00, "2026-10": 265.00}
}
```

`action`: `stay` — остаться, `change` — сменить тариф, `add_packages` — тот же тариф + доппакеты.
Дальше идут расширенные поля для веб-формы: `reason`, `cheapest_option`, `tariff_comparison`
(лучший вариант на каждом тарифе с разбивкой стоимости) и т.д.

Все суммы — средние за месяц, в сомах, округление до 0.01 (HALF_UP) только на выходе;
внутри расчёт в `BigDecimal` без потерь.

## Как считается

1. **Агрегация по месяцам** (`UsageAggregator`): звонок округляется вверх до целой минуты
   (0 сек → 0 мин, 1 сек → 1 мин, 61 сек → 2 мин). Домашнее и роуминговое потребление — раздельно.
2. **Стоимость месяца** (`CostCalculator`): абонплата + доппакеты + перерасход минут/ГБ/SMS сверх
   (пакет тарифа + пакеты доппакетов) + роуминг.
3. **Особые условия:** ночь `[01:00, 07:00)`. На тарифах с `night_unlimited` из расхода исключается
   только пересечение сессии с ночью (трафик распределён по `duration_sec` равномерно; при
   `duration_sec = 0` — по моменту начала). Роуминг не входит ни в пакеты, ни в ночной безлимит:
   цена за округлённую минуту, ГБ или SMS из `roaming_rates`.
4. **Месяцы:** ровно три из `subscribers.json`, включая пустые — абонплата списывается и в месяце
   без потребления.
5. **Перебор** (`Recommender`): все тарифы × комбинации из 0–2 доппакетов (пакет можно взять дважды),
   одна комбинация на все три месяца. Варианты упорядочены по средней стоимости; при равенстве —
   остаться, затем меньше доппакетов, затем `tariff_id`, затем отсортированные `addon_id`.
6. **Окупаемость:** берётся самый дешёвый вариант, который окупается: другой тариф — если экономия × 3
   **строго больше** 50 сом; тот же тариф с доппакетами — если экономия просто положительная (смены
   нет, пакеты бесплатно). Не окупается ни один — `stay`.

Правила — из `CLARIFICATIONS_RU.md` организаторов (§2). Параметры собраны в `Config`
(ГБ/МБ, плата за смену, строгость порога, повторы доппакетов).
